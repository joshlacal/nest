# Circles backend: October 22 Spaces protocol

The Circle AppView indexes permissioned AT Protocol Spaces for Catbird. This implementation follows the upstream Spaces source at `ac0c9f15392f6f0298d71dc52aa88c05036150be`, replacing signed repository commits and CAR recovery with request-specific response MACs and STAR archives. Account lifecycle synchronization and short membership checks gate private serving. Actual Rust transport interoperability has been checked against two local pinned reference hosts; deployed PDS, relay, and device qualification remain release gates.

Governing plan: [Spaces release readiness](/Users/joshlacalamito/Developer/Catbird+Petrel/docs/research/2026-10-23-spaces-release-readiness.md). Lifecycle operation and recovery: [IDENTITY_LIFECYCLE.md](IDENTITY_LIFECYCLE.md).

## October 29 update

The AppView now targets the October 29, 2026 Spaces alpha (atproto `5d88b414a98de1ada22c94c78fa0667a7028163c`), which is also the served `protocolRevision`. Only the space-configuration reads changed:

- `getSpace` moved to `com.atproto.space.getSpace` and returns `{ uri, policy }`. The AppView still calls it, and `com.atproto.memberspace.listMembers` (formerly `com.atproto.simplespace.listMembers`, same shape), under the authority's own OAuth session; its `space:blue.catbird.circle?action=read` grant covers the owner-only `read_self` check.
- The policy union maps onto the existing model. A `com.atproto.memberspace.policy` with `publicRead` and `publicWrite` false is the only supported Circle policy. `allowedApps` replaces `appAccess`: omitted means any app may read, a list naming this AppView's client_id grants, and a list that omits it (including `[]`) is an explicit revocation that purges, as before. A malformed `allowedApps`, a public flag, `managedspace`, `personalspace`, or an unknown `$type` is refused without purging.
- A credential refusal from the reference authority now arrives as `SpaceNotFound`. Activation has already confirmed the Space through `getSpace`, so it keeps answering such a refusal as `Forbidden`; other paths keep their non-destructive, throttled handling. `UserNotAuthorized`, `AppNotAuthorized` and `NotAuthorized` are still handled.
- Sync needs no change: published `com.atproto.space.policy` and `com.atproto.memberspace.member` records in the authority's repo are ignored as unsupported collections, a `clearRecords` digest mismatch goes through the existing full recovery from `getRepo`, and a migrated repo's new `rev` with unchanged `data` advances the checkpoint.

The text below describes the October 22 transport, which is otherwise unchanged; the `reference_transport` fixture now creates its Space with `com.atproto.space.createSpace` and a memberspace policy.

## Wire behavior

Credential exchange resolves the authority's current `#atproto_pds` service and sends only a JSON body containing `space`, `credentialKid`, and the delegation token/client attestation. The exchange carries no proof headers. Authority delegation and credential JWTs require the exact protected `kid` value `#atproto`, the current JWT type, and an algorithm matching the resolved signing key.

Credential use sends `Authorization: Atproto-Space-Credential …` and the required `atproto-space-credential` HTTP signature tag. Every `getLatestCommit`, `listRepoOps` page, and `getRepo` attempt has a new ephemeral P-256 key. The AppView resolves the author's exact `#atproto_kem` P-256 verification method (Multikey or the reference PLC legacy multibase form), uses DHKEM(P-256, HKDF-SHA256), and sends the public share in `Atproto-Space-Want-Mac`. The shared secret is not logged. Returned commits require a valid `Atproto-Space-Mac` for the exact Space, author, revision, and digest before the transport releases them. A page without a commit must not carry a commit MAC. `BadSpaceMac` triggers at most one fresh-DID/fresh-ephemeral retry; it never clears the credential or permits an unsigned fallback.

Nest's generic OAuth proxy preserves the request MAC-share header and response MAC in both buffered and streaming responses. It continues to generate the upstream OAuth authorization and DPoP proof itself.

Full recovery accepts `application/octet-stream` STAR-lite v1 with magic `2a 6c 01 00`, shortest-form varints, canonical DRISL metadata and records, unique byte-sorted record paths, and a recomputed LtHash digest matching the MAC-authenticated commit. All framing and record validation completes before the existing atomic projection replacement transaction. Limits are 50 MiB per archive, 64 KiB metadata, 1 KiB paths, 1 MiB records, and 10,000 records. These are application resource limits; larger otherwise valid repositories fail closed. Historical CAR helpers remain only for old-format rejection/parser regression coverage and are not used by production synchronization.

`notifyWrite` and `listRepos` consume the current `data` digest field. Persisted `last_hash` remains the internal 2,048-byte LtHash accumulator; its database name is not a wire-format claim.

## Private serving

Membership information expires after 30 seconds. Feed, thread, notification, and Circle-list reads check membership again after assembling the response, so profile hydration cannot extend an expired membership decision. Unreadable membership or OAuth refresh fails closed. Suspended/deactivated authors and authorities are excluded by the account-status ledger, and inactive requesters are denied. The final sync transaction locks and rechecks author and authority account status before publication. Lifecycle source readiness also gates capabilities and authenticated routes.

Deliberate reactivation of a retired Circle clears retained credentials and projections before a fresh adoption. Terminal account deletion does not automatically reactivate.

`supportsImages` is `false`. The public media route refuses requests, and post views omit rendered image embeds. The private media implementation remains available to local regression tests, but private blob serving has not been qualified on supported hosts. Circles remain permissioned plaintext records; this work adds neither public fallback nor an MLS encryption layer.

## Local validation and release boundary

The Circle AppView pins `catbird-atproto` to the published Git revision `f40e8795ff8690092440971a9b5e5496e3f8430f` (October 29 Spaces bindings); the Nest gateway, which uses no Spaces bindings, stays at `d6638bb5237e3d7bf9f6ac34d958fa2d61da2aad`. Neither build uses a sibling path override. Docker builds require their committed Cargo lockfiles.

The tests include the RFC 9180 P-256 DHKEM vector, an independently computed HMAC context vector, context and body tampering, missing/wrong response MACs on real loopback HTTP transport, fresh keys per page/retry, STAR structural/digest failures, SQLx projection/privacy regressions, and account lifecycle confirmation/replay tests. Injected host responses and explicitly seeded healthy ledger rows are fixtures. They prove local code behavior only.

The opt-in `reference_transport` integration test exercises `DefaultSpaceHostTransport` against running TypeScript reference servers at the exact source revision above. It verifies body-only authority exchange, the authority signature and key binding, then `getLatestCommit`, `listRepoOps`, and complete `getRepo` STAR reads on two hosts. The fixture contains two synthetic posts; this is protocol interoperability evidence, not AppView synchronization, OAuth consent, relay recovery, or capacity evidence. The test does not log credentials, keys, record contents, or private selectors.

For an existing synthetic loopback lab, run `node scripts/prepare_reference_transport_fixture.mjs ACCOUNTS_JSON PRIVATE_CONTEXT_JSON PLC_ORIGIN`, then `CIRCLE_REFERENCE_CONTEXT=PRIVATE_CONTEXT_JSON cargo test --locked --test reference_transport -- --ignored --nocapture`. The preparer creates an additive, separately named Space and one record on each synthetic member account. It writes the short-lived delegation context with mode `0600` and refuses to overwrite an existing file. Keep both account input and context outside version control; the test generates its own fresh credential-signing key. Loopback access is selected only by this explicit test fixture, never by production startup.

Release still requires a configured and caught-up trusted relay, tests against a pinned supported PDS with KEM rotation and account migration, the private-blob matrix before enabling images, and the Catbird device privacy scenarios in the governing plan. No production deployment, database migration, restart, or cursor reset was performed by this task.
